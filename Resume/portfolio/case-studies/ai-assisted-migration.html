Custom agent skills that compress migration assessment

Context Reusable methodology across engagements Role Author and practitioner Scope Internal tooling and delivery method

Problem

BI platform migrations start with assessment, and assessment is where they stall. Before anyone can estimate a Tableau-to-Power BI migration, someone has to inventory the existing reports, trace data sources and dependencies, understand the business logic embedded in calculations, identify which reports are actively used versus abandoned, and judge conversion complexity.

Done manually across a few hundred reports, this takes weeks. It is repetitive, it is inconsistent between analysts, and it is the part of the engagement where customers lose patience — because they are paying for analysis before seeing anything built.

Worse, the output quality depends heavily on who did it. Two analysts assessing the same estate routinely produce different complexity ratings and effort estimates, which undermines confidence in the plan that follows.

Repetitive, rule-governed analysis that produces inconsistent results depending on who performs it is precisely the shape of problem automation handles well — provided a human still reviews what comes out.

Approach

Rather than using AI ad hoc, I encoded the assessment methodology itself into reusable agent skills — so the process runs consistently regardless of who invokes it.

  • Wrote custom agent skills capturing assessment steps as explicit, repeatable instructions rather than prompts retyped from memory each time.
  • Built reusable prompt and instruction libraries so analysis followed a defined sequence with defined outputs.
  • Connected agent tooling to the systems holding the artifacts, so analysis ran against actual report definitions and model metadata rather than descriptions of them.
  • Used agentic patterns to inspect and validate semantic models and report definitions programmatically.
  • Built human review into the workflow at defined checkpoints — the agent produces analysis, a person validates it before it informs any customer commitment.

Solution

A working set of skills and libraries covering the analysis-heavy phases of migration and modernization work.

  • Migration assessment. Automated inventory, dependency analysis, and complexity scoring of source reports, with extraction of embedded business logic.
  • Semantic model review. Structured evaluation against modeling best practice, surfacing relationship problems, ambiguous grain, and AI-readiness gaps.
  • Report conversion analysis. Feature-level mapping between source and target platforms, flagging constructs with no clean equivalent.
  • Application modernization assessment. The same pattern applied to legacy .NET portfolios for scoping and risk identification.

Outcome

  • Weeks of assessment became days. Inventory and analysis work that previously consumed the opening phase of an engagement compressed substantially.
  • Output became consistent. Encoding methodology into skills removed most of the variance between analysts assessing the same estate.
  • Customers saw progress sooner. Shorter assessment meant reaching demonstrable build work earlier, which changed the tone of engagements.
  • Reusable across engagements. The skills carried forward rather than being rebuilt each time, and improved with each application.
  • Human judgment stayed in the loop. Every output is reviewed before informing a customer commitment. Speed came from automating analysis, not from removing accountability.

Methodology described in general terms. No client data, proprietary code, or confidential information is represented here. Any tooling referenced would be rebuilt independently for commercial engagements.
